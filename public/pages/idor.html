Look up your order details by entering your order ID.

2. The server doesn't check if the order belongs to you. Try IDs 1 through 20.

Change the order ID to any number between 1 and 20. The server returns every order regardless of who placed it. There is no ownership validation — classic IDOR.

Order Lookup

🚨 IDOR Detected! You accessed an order belonging to another user. The server returned it without verifying ownership — any sequential ID works.

How It Works

When you look up an order, the app sends:
GET /api/orders/3

The server returns the order data — but does it check if the order is yours?

Vulnerable Code

Server returns any order without ownership check:

// VULNERABLE: no ownership validation
app.get('/api/orders/:id', (req, res) => {
  const row = db.prepare(
    'SELECT * FROM orders WHERE id = ?'
  ).get(req.params.id);
  res.json(row);
});

// Safe alternative:
// WHERE id = ? AND user_id = ?
🦆

When object IDs are sequential and unvalidated, users can access other people's records by guessing. The server trusts the ID you send without checking if you own that resource.

Think of it like: Trying locker number 101 when you only own locker 100 — and the lock just opens.

Real world: 2021 Instagram API exposed private user data via sequential account IDs with no authorization checks.
