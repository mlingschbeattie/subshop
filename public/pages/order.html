📁 Case File — Insecure Design
SituationThe online ordering system calculates prices on the client side using a hidden form field before submission.
At RiskRevenue integrity — customers could manipulate prices before the order reaches the server.
Your RoleModify the order price before it reaches the server. Prove the design flaw in client-side pricing.
ORDER ONLINE

Order Online

Customize your sub and place your order for pickup or delivery.

1. Open DevTools and inspect the order form carefully.
2. Not all form fields are visible. Look for input[type="hidden"].
3. The price is stored in a hidden field. Can you change it before submitting?
Inspect the form in DevTools, find the hidden <input name="price"> field, change its value to 0.01, then place the order. The form submits whatever price you set — the server trusts it blindly.

If the price is calculated and stored in the browser, the user controls the price. Hidden fields are hidden visually — not from DevTools or request interceptors.

Think of it like: A price tag you're allowed to write on yourself before checkout — the cashier trusts whatever you wrote.

Real world: 2020 multiple e-commerce sites exploited via hidden form field price manipulation.
